# 病例 0009：病程时间线被污染——「一天掉 16 GB」其实是假的

## 1. 症状

- `trend` 显示宿主机可用空间一天内从 90.5 GB 掉到 77.2 GB，中间还有一次 **22.9 GB** 的深坑
- 换算下来 `volume.freeGB` 每天 -16.674 GB，看起来像严重泄漏
- 用户问：这 16 GB 去哪了？

## 2. 环境

| 项 | 值 |
|---|---|
| 主机 | DESKTOP-KFSCV8C（本机，非管理员执行探针） |
| 系统 | Windows 11 Pro 26200 / PowerShell 5.1 |
| 引擎 | v3.7.1 |
| 数据 | `C:\ProgramData\cdrive\state\trend.jsonl`（54 条） |

## 3. 采集（证据）

### 3.1 时间线本身就不合理

```
10-24 22:04  90.5 GB
10-24 22:05  22.9 GB   Δ -54.3
10-24 22:08  90.4 GB   Δ +67.5
10-25 12:00  77.2 GB   Δ -12.8
10-25 17:26  88.9 GB   Δ +11.7
```

### 3.2 按来源分组立刻见分晓

```powershell
$recs | Group-Object origin
# local            53 条   freeGB 77.2 – 93.5
# remote:win11-test 1 条   freeGB 22.9   ← VM 的 C 盘
```

### 3.3 再看时间戳的真实性

```
storage-findings.json      generatedAt = 2026-10-23T22:08
存进 trend 后               ts          = 2026-10-25T12:00   ← 记录时刻，不是测量时刻
```

也就是说：**10-23 测到的 77.2 GB，被贴上了 10-25 12:00 的标签**。

## 4. 假设与排除

| 假设 | 判据 | 结果 |
|---|---|---|
| 页面文件暴涨 | 物理内存 31.9 GB；C: pagefile 分配 2 GB / 上限 4.9 GB | 排除 |
| 休眠文件 | `C:\hiberfil.sys` 不存在 | 排除 |
| Windows 更新暂存 | `SoftwareDistribution\Download` = 0 GB；`Windows\Temp` = 0 GB；无 `$WinREAgent` / `Windows.old` | 排除 |
| 近期大文件 | 12:00 后 >500 MB 的新文件仅 1 个（Edge 0.67 GB） | 排除 |
| 卷影副本堆积 | 非管理员无法查询（`vssadmin` 初始化失败） | 未能验证 |
| **远端记录混入本机序列** | origin 分组显示 1 条 `remote:win11-test`，值 22.9 GB | **成立** |
| **旧测量配新时间戳** | findings.generatedAt 与 trend.ts 不一致 | **成立** |

## 5. 处置

| 动作 | 影响面 | 可回滚 |
|---|---|---|
| `Get-TrendRecords -Origin`（默认 `local`），报告标注来源 | 所有趋势输出 | 是 |
| `ts = findings.generatedAt`，缺省用文件修改时间 | 记录逻辑 | 是 |
| 按 `(origin, ts, probeSet)` 去重 | 记录逻辑 | 是 |
| 新增 `trend --rebuild`：以测量时间重建序列，自动备份 | 数据修复 | 是（有 .bak） |
| 每日任务改为 `scripts/trend-daily.ps1`：**先 probe 再 record** | 调度 | 是 |

## 6. 结果

```
重建后：local 65 条，10-23 23:05 → 10-25 17:28（1.67 天）
volume.freeGB：77.2 → 88.9 GB    变化 +11.7 GB    +6.99 GB/天
```

- 是否解决：是。宿主机**空间在变多**，不存在 16 GB 泄漏
- 22.9 GB 深坑：VM 的一条记录，已隔离
- 77.2 GB「暴跌」：10-23 的真实测量被误标成 10-25

## 7. 教训

1. **事实层的错误比动作层更危险**：动作错一次看得见；数据错会让人一直做错误判断
2. 每一条时间序列都必须标注**两个元数据**：来源（哪台机）与测量时刻（什么时候测的），缺一不可
3. 跨机数据一律隔离，宁可分开看，也不要混成一条「看起来更完整」的曲线
4. 排查结论要能解释**所有**异常点；只解释一半，通常是还没找到根因
