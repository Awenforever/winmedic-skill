# 病例 0014：视频「复制到电脑后时间跳到未来」（相机元数据 +8 小时）

## 1. 症状

- U 盘（H:）里视频的修改时间正常
- 复制到电脑 E: 后，Explorer 某列显示的时间**比现在更晚**（例如 15:50 时看到 19:41 / 22:12）
- 用户怀疑「文件未卜先知」或拷贝过程改了时间

## 2. 环境

| 项 | 值 |
|---|---|
| 主机 | DESKTOP-MGCJK2F（ustc-wmw），Windows 11 |
| 源盘 | H:，exFAT，Sony 相机 `PRIVATE\M4ROOT\CLIP` |
| 目标盘 | E:，NTFS，`实验数据\低压舱\双元燃料\He` |
| 系统时区 | China Standard Time（UTC+8，无 DST） |

## 3. 采集（只读）

| 文件 | U 盘修改时间 | E: 修改时间 | MP4 元数据 `creation_time` | Explorer「创建媒体日期」 |
|---|---|---|---|---|
| C0007.MP4 | 13:01:49 | **13:01:49** | 11:41:04 | **19:41** |
| C0008.MP4 | 14:57:10 | **14:57:10** | 14:12:12 | **22:12** |

关键比对：

- 两处**文件系统修改时间逐秒一致** → 拷贝没有改时间
- 元数据 + 8 小时 = 截图显示值（11:41:04 + 8h = 19:41；14:12:12 + 8h = 22:12）
- Shell 列索引 214「创建媒体日期」返回 19:41；同文件的 `System.DateModified` 返回 05:01（UTC）

## 4. 假设与排除

| 假设 | 判据 | 结果 |
|---|---|---|
| 拷贝工具改了时间戳 | 两处 FS 修改时间一致 | **排除** |
| 时区换算错误（固定 +8 偏移） | 偏移精确为 +8h，且只出现在元数据列 | **支持** |
| 文件系统 FAT/exFAT 时间语义差异 | 源和目标 FS 时间一致 | **排除** |
| 同步软件改写 | 无相关进程；E: 上创建时间 = 拷贝时间 | **排除** |
| **相机把本地时间当 UTC 写入元数据** | 元数据时间 = 本地时间，查看器按 UTC→本地转换 | **成立** |

## 5. 处置（政策：源头根治，不逐个修正）

**第一优先：相机端改正时区**

- 进入相机菜单，把**时区设为 UTC+8**（Sony 通常在 设置 → 区域/日期时间）
- **只改时区，不要改时钟**；否则文件系统时间也会跟着错
- 改完后拍一段测试片，元数据应与本地时间一致（不再 +8）

**日常查看：换列，不换文件**

- 在 Explorer 用「修改日期」或「创建日期」列；不要用「日期 / 创建媒体日期」列做时间线

**不推荐：批量重写元数据**

- `ffmpeg -c copy -metadata creation_time=...` 虽然不重编码，但要**整文件重写**（31 GB 级别很慢）且生成副本
- 逐个修正既费时又容易出错，且下次拍摄还会复现
- 只有归档/取证等确需一致时间线时才做，并先备份

## 6. 结果 / 验证

- 本次未修改任何文件（只读审计）
- 已确认：文件系统时间正确，问题只存在于「媒体元数据」显示层
- 验证方式：相机改时区后拍新片，检查 `创建媒体日期` 是否等于实际拍摄本地时间

## 7. 教训

1. **区分两种时间**：文件系统时间戳（NTFS/exFAT）与媒体元数据（MP4 `creation_time`）是两套东西
2. **`System.DateModified` 返回 UTC**，而 Explorer 显示本地时间；直接比字符串会误判 8 小时
3. **列的含义决定结论**：同一文件夹，「修改日期」正确、「创建媒体日期」错 8 小时
4. **修源头而不是修产物**：相机时区一次改对，胜过以后逐个文件重写

## 8. 对 winmedic 的意义

当前引擎没有媒体/时间线域，无法自动判断「FS 时间与元数据不一致」。
可考虑的探针（未来）：`probe --set media` —— 抽样视频，比对 FS 修改时间与元数据时间差，超过阈值（如 ±1h）即告警，并提示检查拍摄设备时区。

## 9. 引擎侧验证（v1.5.0）

- `probe --set media` 新增 `moov/mvhd` 自解析，不依赖 Shell 属性
- 用本案真实文件验证：31 GB XAVC，`moov` 位于 31.4 GB 的 `mdat` 之后，按 box 跳转可直接定位；
  解析出的 UTC `2026-11-01 11:41:04` 与 Shell `DateEncoded` 完全一致
- `diagnose --case dx.media-timestamp` 可直接给出偏移事实，不再需要人工拿 Explorer 对照
