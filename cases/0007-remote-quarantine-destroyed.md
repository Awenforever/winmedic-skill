# 病例 0007：远端隔离区会随暂存目录一起被删

## 1. 症状

- 远端 `remote-apply` 显示成功，但随后 `remote-restore` 报「隔离区文件已不存在」
- 数据实际上被销毁，而不是「暂存」

## 2. 环境

| 项 | 值 |
|---|---|
| 主机 | win11-test VM |
| 引擎 | v3.2.1 |

## 3. 采集（证据）

```
首次 remote-apply: runId=20261024-213433-5a0398，暂存目录 C:\...\Temp\winmedic-20261024-213412
随后 remote-restore: 恢复失败，隔离区路径已不存在
```

## 4. 假设与排除

| 假设 | 判据 | 结果 |
|---|---|---|
| restore 逻辑错误 | 本机 selftest 8/8 通过 | 排除 |
| 隔离区没建 | `remote-apply` 报 R2 完成 | 排除 |
| **隔离区建在暂存目录内，被清理连带删除** | CDRIVE_HOME 指向 `Temp\winmedic-*` | **支持** |

## 5. 处置

| 动作 | 影响面 | 可回滚 |
|---|---|---|
| 新增持久状态目录 `C:\ProgramData\winmedic-remote-state` | 远端 | — |
| 只清理引擎暂存包，不清理状态目录 | 远端 | — |
| 审计日志自动拉回本地 | 本地 state | — |

## 6. 结果

- 是否解决：是。复测 120 MB 移动 → 远端还原，3 个文件 SHA256 一致
- 代价：首次实验销毁了 120 MB 测试数据（自造负载）

## 7. 教训

- **「隔离区」必须是持久存储**，不能放在任何「执行完就清理」的目录里
- 远端能力的默认清理语义必须比本地更保守：宁可留垃圾，不可删证据
