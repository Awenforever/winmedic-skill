# 缓存/数据放哪：决策程序（不是规则表）

> 用户说「帮我把缓存都搬到 D 盘」时，**不要照做，也不要查表**。
> 工具只给事实；方案由你结合盘况、软件行为、用户习惯判断，并说明理由。

## 第 0 步：先取事实

```powershell
.\engine\winmedic.ps1 relocate
```

输出三段，含义不同：

| 段 | 是什么 | 怎么用 |
|---|---|---|
| 决策清单 | 3 个必须回答的问题 | 在回答里逐条给结论，**不许跳过** |
| 事实 | 路径/体积/介质/是否存在/已知文件夹/软件声明路径 | 判断依据 |
| 默认建议 | 引擎的默认视角（`policySource=default-hint`） | **只是参考**，可推翻 |

## 第 1 步：逐条回答清单（必须）

### Q1 它在已知文件夹下吗？

看事实表的 `已知文件夹` 列。命中时：

- 正确动作是**移动那个文件夹一次**，不是给每个软件设路径
- 但它未必是最优解 —— 先做 Q3

### Q2 热数据还是冷数据？

这题**没有表可查**，按用途判断：

| 判断线索 | 倾向 |
|---|---|
| 程序运行中高频读写、丢了会自动重建（渲染缓存、索引、流媒体缓存） | 热 → 留最快盘 |
| 只在用户主动打开时读、体量大、删了要重新下载（游戏、虚拟机、素材、书库） | 冷 → 可搬容量盘 |
| 是配置/登录态/插件 | 不动 |

**关键反例**：Photoshop 暂存盘、Premiere 媒体缓存都是热数据。它们体积大，但搬到机械盘会让每一步操作都卡。**「大」不等于「该搬」。**

### Q3 软件是否已记录绝对路径？

看事实表 `软件声明路径` 列（微信 `FileSavePath`、Steam `libraryfolders.vdf`、JetBrains `idea.properties`）。

- **有值** → 先装后搬：移动目录后必须改软件内设置，否则它会指回旧路径或在原处重建空目录
- **无值** → 先搬后装：只移动文件夹即可，之后软件自然落位
- **判断不确定** → 用 `exists` 列：目录已存在且里面有数据 = 软件正在用 = 先装后搬

## 第 2 步：出方案（格式固定）

对每个待处理项写四行：

```
【软件/目录】当前在 X（介质），体积 N GB
【判断】热/冷 + 是否已知文件夹 + 是否已记录路径
【方案】搬 / 不搬 / 先改软件设置；目标盘 = Y（介质，剩余 Z GB）
【风险与验证】搬完怎么确认没坏（打开软件 → 看原路径是否重建 → 看数据是否可见）
```

**必须让用户确认后才执行**；引擎不代你搬。

## 第 3 步：如果需要移动已知文件夹

```
正确方式：资源管理器 → 右键该文件夹 → 属性 → 位置 → 移动（底层是 SHSetKnownFolderPath）
错误方式：手改注册表 User Shell Folders、用 mklink /J 做假目录
```

移动后按 Q3 检查每个受影响的软件。

## 红线

- 不把热数据搬到机械盘
- 不在软件运行时搬数据目录
- 不把配置当缓存搬
- 目标盘剩余空间 < 数据量 × 1.2 时不搬
- 用户只说「清出 C 盘」时，先给「清理 vs 迁移」两条路的代价对比，别默认选迁移
