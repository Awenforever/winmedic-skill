# 清理协议（所有破坏性动作的前置）

> 只要任务包含删除、清空、卸载残留、清缓存、删启动项中的任意一项，必须先读本协议。

## 铁律

1. **先证明它是垃圾，再动手。** 不知道是什么的东西，一律不动。
2. **能不删就不删，能迁移就别删。** 用户的痛点是「空间不够」，不是「文件太多」。
3. **删之前先问能不能回滚。** 不能回滚的，必须逐项确认。
4. **用户说不要动的，写进约束，全程遵守**，即使它看起来是垃圾。

## 执行顺序

```
只读采集 -> 分级报告 -> 用户勾选 -> 隔离区执行 -> 验证 -> 出报告
```

## 分级

| 级别 | 判定标准 | 处理 |
|---|---|---|
| 1 | 删了系统/软件照跑，且能重建或本来就没用 | 确认后执行 |
| 2 | 缓存类，删了会自动重建 | 说明重建代价后执行 |
| 3 | 可能影响功能，或需要重启才生效 | 逐项确认 + 展示证据 |
| 4 | 红线 | **拒绝**，给人工路径 |

## 禁止的删除方式

- 不用 `Remove-Item -Recurse` 直接删用户目录 —— 走隔离区
- 不删 `Windows\Installer`、`WinSxS` 内部文件、`System32`、`WindowsApps`
- 不碰聊天记录目录（`WeChat Files` / `xwechat_files`）
- 不为了「省空间」重建搜索索引（几天就长回来）
- 不在只剩 1–2 个还原点时删还原点

## 必须转人工的情况

- 需要判断某个文件是否是用户的重要资料
- 涉及授权/加密（BitLocker 恢复密钥、软件许可证）
- 目标正在被系统或用户程序独占且无法安全停止
- 用户要求「全部删掉，不用管风险」

## 报告要求

固定回答四件事：**它是什么 / 多大 / 删了会怎样 / 能不能恢复**。
缺任何一项就不要建议删除。
