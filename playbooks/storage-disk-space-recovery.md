# 磁盘空间恢复（C 盘爆满）

## 适用

用户说：C 盘红了、空间不足、只剩几个 G、装不上东西、桌面堆满。

## Step 1: 只读体检

```powershell
.\engine\winmedic.ps1 doctor
.\engine\winmedic.ps1 probe --set storage
```

拿到：容量、可用空间、候选清单（含大小与级别）。**此时不要建议任何删除。**

## Step 2: 判断痛点性质

| 现象 | 通常病因 | 走向 |
|---|---|---|
| 可用空间 < 10% 且长期 | 分区规划不合理（C 太小、其他盘空着） | 见 PB-103 分区审计 |
| 突然变少 | 更新残留、休眠文件、回收站、日志暴涨 | 本 playbook |
| 缓慢变小 | 缓存/聊天记录/下载目录增长 | 本 playbook + PB-302 迁移 |

**先问一句：这块盘是系统盘独占，还是和 D 盘同一块物理盘？** 同一块盘上 C 小 D 空，清理只能缓解，不解决。

## Step 3: 生成方案

```powershell
.\engine\winmedic.ps1 plan
```

把 `plan.md` 原文给用户看。**不要自己改写成模糊描述。**

重点告知三件事：
1. 合计能释放多少
2. 哪些项需要先关程序/需要管理员
3. 哪些项**不可回滚**（当前 storage 域几乎都可回滚，WinSxS 清理除外）

## Step 4: 执行

```powershell
.\engine\winmedic.ps1 apply --plan state\plan.json --ids R1,R2 --yes
```

规则：
- 用户说「都行」→ 只做 Tier 1 + Tier 2
- 前置未通过的项会被跳过并记 journal，**不要强行绕过**（例如 Edge 在跑就不要杀它再删）
- 不要加 `--purge`

## Step 5: 验证与交付

```powershell
.\engine\winmedic.ps1 verify --journal <runId>
```

- 报可用空间变化，不要只报「已清理」
- 若 `pendingReboot` 为真，明确说「重启后才完全生效」
- 给出未做项及原因

## 常见误判（必须避免）

| 误判 | 事实 |
|---|---|
| 「回收站才几 MB」 | 可能藏着 GB 级遗留物（如升级迁移包），按 SID 逐个看 |
| 「Package Cache 一定是开发工具」 | 可能全是显卡驱动旧包，读 readme 才知道 |
| 「删了缓存空间立刻涨」 | WinSxS 清理后当场可能反而下降，CBS 日志 + Temp 要重启才释放 |
| 「休眠文件不影响开机」 | 若快速启动开着，关休眠会同时关快速启动，开机变慢 |
| 「页面文件可以全删」 | 会失去蓝屏转储；且提交上限可能不够，导致 OOM |

## 停手条件

- 候选里出现聊天记录目录 → 立即排除
- 用户已声明保留项出现在方案里 → 立即排除并说明
- 只剩 Tier 3/4 项时 → 交给用户决定，不要自行扩大范围
