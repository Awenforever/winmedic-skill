# 邮箱连通性分诊

## 适用
「密码没错但一直提示重新输入」「能收不能发」「公司邮箱配不上」「新电脑配邮箱」。

## Step 1: 先分清「认证失败」还是「连不上」

| 提示 | 含义 | 方向 |
|---|---|---|
| 反复输入密码 | 认证失败 | 密码/二次验证/应用专用密码 |
| 无法连接到服务器 | 网络/端口 | 代理、防火墙、端口 |
| 证书错误 | TLS/中间人 | 公司代理或过期证书 |
| 能收不能发 | SMTP 被拦 | 运营商 25 端口封锁最常见 |

## Step 2: 确认账户参数（问用户要，不要猜）

- 账户类型：Exchange / IMAP / POP3
- 服务器与端口：IMAP 993(SSL)、SMTP 465/587(SSL/TLS)、POP3 995(SSL)
- 是否开启二次验证 → 多数服务需要「应用专用密码」

## Step 3: 连通性测试（由 Agent 显式执行，引擎不联网）

```powershell
Test-NetConnection imap.example.com -Port 993
Test-NetConnection smtp.example.com -Port 587
Resolve-DnsName imap.example.com
```

| 结果 | 结论 |
|---|---|
| DNS 解析失败 | 域名写错或 DNS 问题 |
| 端口不通 | 网络/防火墙/运营商封锁 |
| 端口通但认证失败 | 账号或授权码问题 |

## Step 4: 国内常见坑

- **企业邮箱需要授权码**，不是登录密码
- **运营商封锁 25 端口**：改用 465/587
- **公司代理**：Outlook 走系统代理，Clash 之类可能拦掉
- **QQ/163 邮箱**：必须先在网页端开启 IMAP/SMTP 并生成授权码

## Step 5: 报告

给出「认证失败还是连接失败 → 证据（端口/DNS 结果）→ 需要用户提供什么 → 下一步」。

## 红线

- 不让用户在聊天里贴密码（要贴就贴授权码，并提醒事后重置）
- 不猜测服务器地址，以服务商官方文档为准
