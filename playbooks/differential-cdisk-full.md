# C 盘空间不足：鉴别诊断

## 适用
「C 盘又红了」「删了缓存还是满」「不知道为什么一直涨」

## 第 0 步：取事实（不看结论）

```powershell
.\engine\winmedic.ps1 diagnose --case dx.cdisk-full
```

输出是**事实表**，不含结论。你要做的是逐条判断。

## 第 1 步：按假设排除

| 假设 | 怎么排除 | 排除后说明 |
|---|---|---|
| 休眠文件 | `powercfg /a` 看是否启用；值与内存对比 | 关闭休眠可立即释放，但会失去快速启动 |
| 回收站 | 值接近 0 即排除 | 清空即可 |
| 浏览器缓存 | 值 <1 GB 即排除 | 可清，但收益小 |
| 应用缓存 | 看具体条目（腾讯系/OneDrive） | 混合目录要逐项确认 |
| 软件缓存 | 需要 `probe --set workloads` | 区分 cache 与 data，data 绝不删 |
| **近期异常增长** | 需要 2 条以上 `trend` 快照，`confidence=ok` 才能算速率 | **这是真正的病因线索** |
| 还原点/卷影 | `vssadmin list shadowstorage` | 系统保护占用 |

## 第 1.5 步：别只看系统项（数据驱动目标表）

引擎的 `catalog/cleanup-targets.json` 目前覆盖 **40 个清理目标**，其中很多是「表面看不见但很大」的：

| 类别 | 例子 | 典型体积 |
|---|---|---|
| 浏览器衍生缓存 | Edge/Chrome Service Worker、着色器缓存 | 数百 MB 到 1 GB+ |
| 开发缓存 | pip / npm / NuGet / Gradle | 几十 MB 到数 GB |
| 崩溃与日志 | 用户崩溃转储、WER、CBS 日志 | 百 MB 级 |
| 协作/模型 | Teams、Slack、HuggingFace 模型缓存 | HF 可达数十 GB |

所以「C 盘满」的结论不要停在 `Windows` 与用户文档——先看 `probe --set storage` 的 `probe.cleanup-targets` 明细。

## 第 2 步：区分「治标」与「治本」

- 缓存类：清了会回来 → 治标，只在空间告急时做
- 增长类：找到「谁在涨」→ 治本
- 结构类（组件膨胀、虚拟机、WSL 虚拟盘）：要么迁移，要么扩容

## 第 3 步：出方案

```
【判断】哪些假设被排除、哪些被证据支持
【方案】清理 / 迁移 / 处置增长源；每项给出预期回收量与风险
【验证】处置后 7 天再 trend 一次，确认增长停了
```

## 红线

- 不删用户数据（聊天记录、文档、虚拟机磁盘）
- 不做注册表清理（伪优化）
- 未确认增长率前，不要承诺「清理后不会再满」
